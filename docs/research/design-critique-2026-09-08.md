# Design Critique — RPG Build Optimizer (2026-09-08)

## Overview

**Scope reviewed (JSX + Tailwind classes only, no live rendering):**
`src/components/App.tsx`, `landing.tsx`, `landingSteps.ts`, `ImportPanel.tsx`,
`ArtifactForm.tsx`, `OptimizePanel.tsx`, `Results.tsx`, `SampleGear.tsx`,
`GapSection.tsx`, `GapReport.tsx`, `ExplainBuild.tsx`, `BuildCard.tsx`,
`src/roster/RosterView.tsx`, `src/teams/TeamsView.tsx`, `src/plan/PlanView.tsx`,
`src/index.css`, `tailwind.config.js`, and every file in `src/components/ui/`
(`Badge`, `Callout`, `Marker`, `Meter`, `Segmented`, `CharacterLine`,
`Disclosure`, `ElementName`, `SearchCounts`, `SourceLink`, `GradeMarker`,
`Drawer`, `Glyphs`, `Combobox`, `cn`, `tone`, `elementTone`).

**Methodology:** static code review only — JSX structure, Tailwind utility
classes, ARIA attributes, and inline comments were read directly; nothing was
run in a browser or dev server. Contrast, spacing, and layout are inferred
from the design tokens (`tailwind.config.js`, `index.css`) and from the
extensive in-code rationale comments the codebase already carries (many
findings a typical audit would raise — focus-visible rings, `aria-disabled`
vs `disabled`, live-region timing, `scroll-margin-top` under the sticky nav,
placeholder-contrast tuning — are already handled and documented in-line, so
this report does not re-flag them). Findings below are the gaps that remain
after that baseline.

**Overall impression:** this is a materially more mature codebase than a
typical review target — accessibility and interaction-state reasoning is
written directly into the JSX as comments, live regions are centralized and
keyed correctly, and there is one shared token system (`tone.ts`,
`elementTone.ts`, `.panel`/`.card`/`.well`/`.chip`/`.btn-*` recipes) that every
file composes rather than reinvents. Findings here are narrower and lower
severity than the prompt's checklist implies for a typical app.

## Cross-cutting consistency issues

1. **No warning/caution tone exists in the shared design system.** `TONE` (in `ui/tone.ts`) covers info/success/error/muted/interactive but not "caution" — and the two places that need one (`RosterView.tsx:58-62`, `PlanView.tsx:143-149`) each reach for a different substitute (`flux`, plain `muted`), which is itself an inconsistency layered on top of the missing token. This is the single highest-leverage fix in this report: one new token would resolve three findings at once.
2. **Success-state treatment is inconsistent.** `ImportPanel` and `ArtifactForm` both wrap their success confirmations in `Callout tone="success"`; `GapReport`'s "all met" message does not, despite being semantically the same kind of event (a positive, non-interactive confirmation). A reader who has learned "green box = good news" from the import flow won't get that same visual cue on the gap report.
3. **Destructive actions have no shared recipe.** `.btn-primary` and `.btn-ghost` are both defined once in `index.css` and composed everywhere; the one destructive action in the reviewed files (`ImportPanel`'s Clear Inventory) is styled inline instead, which will drift further the next time a destructive control is added elsewhere.
4. **Small decorative SVGs are duplicated instead of shared** in two places (`RosterView.tsx` row chevron, `Combobox.tsx` trigger chevron) even though the app already has a `Glyphs.tsx` convention built for exactly this (filled marks); the stroke-based chevrons weren't folded into it.
5. **Everything else — spacing scale, border-radius hierarchy, focus rings, live-region wiring, touch targets, form labeling** — is consistent across all seventeen files reviewed. `.panel`/`.panel-sm`/`.panel-md`/`.card`/`.well`/`.chip`/`.field`/`.btn-primary`/`.btn-ghost` are used verbatim everywhere rather than redefined per view, and every interactive control checked has either an explicit `<label htmlFor>`/wrapping `<label>` or an `aria-label`.

## Priority recommendations (ranked)

1. **Add a `warning` tone to `ui/tone.ts`** and route `RosterView`'s "no gear found" note and `PlanView`'s "no curated recipe" note through it. Highest leverage — fixes three related findings with one change.
2. **Wrap `GapReport`'s "all met" message in `Callout tone="success"`** to match the success pattern established in `ImportPanel`/`ArtifactForm`.
3. **Add a `.btn-danger` recipe to `index.css`** and use it for `ImportPanel`'s Clear/Confirm Clear button, removing the ad hoc rose overrides.
4. **Re-examine the `SampleGear` heading's visual weight** relative to numbered `Section` headings so it reads unambiguously as a shortcut, not step 0.
5. **Extract a shared `ChevronGlyph`** into `ui/Glyphs.tsx` and use it in both `RosterView.tsx` and `Combobox.tsx` instead of duplicating inline SVG markup.
6. **Add a one-line "no curated recipe" fallback to `GapSection`** for non-meta characters, mirroring the message `PlanView.MemberCard` already shows in the equivalent case.
7. **Add a small external-link glyph to `SourceLink`** so sighted users get a visual cue before leaving the app, not just the `sr-only` text.
8. _(Optional, low urgency)_ Revisit the Combobox's sub-44px option-row height on touch viewports specifically, leaving desktop density unchanged — already tracked internally per the in-code comment referencing issue #101.
